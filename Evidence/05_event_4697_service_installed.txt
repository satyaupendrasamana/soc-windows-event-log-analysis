ANALYST NOTE:
A new service, "WinUpdateHelper", was installed running as LocalSystem
(the highest-privilege account on Windows). The name is deliberately
disguised to resemble a legitimate Windows Update component. This
represents the persistence stage of the attack chain — a mechanism
designed to preserve attacker access even if the original compromised
account's password is later changed.

CONFIGURATION GAP DISCOVERED DURING THIS INVESTIGATION:
This event initially did NOT appear in the Security log after the service
was first created. Root cause: the "Security System Extension" audit
subcategory was set to "No Auditing" by default on this machine
(confirmed via `auditpol /get /subcategory:"Security System Extension"`).
It was enabled via:
    auditpol /set /subcategory:"Security System Extension" /success:enable /failure:enable
after which the service was recreated and Event 4697 was correctly logged.
This is a real, generalizable finding: default Windows audit policy does
not capture every security-relevant event out of the box.
